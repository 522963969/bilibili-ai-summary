## 0. 上传前必须由你决定的两件事

1. **隐私政策必须是一个可公开访问的 URL。** 后台不接受本地文件。最省事的做法：把根目录的 `PRIVACY.md` 推到 GitHub 仓库，用 `https://raw.githubusercontent.com/522963969/bilibili-ai-summary/main/PRIVACY.md`（仓库已建好，这个地址现在就能用），或 GitHub Pages 地址。填进内容前请把文末的邮箱与仓库地址补全——**留占位符会被审核打回**。
2. **名称里的「B站」是哔哩哔哩的商标。** 商店政策禁止暗示与官方有关联。目前名称为「B站 AI 视频总结」，被投诉或人工审核拦下的概率不低。三个选项：
   - 保持现状，在详细描述第一行明确写「非官方扩展，与哔哩哔哩无隶属关系」（风险仍在）
   - 改名为「视频字幕 AI 总结（B 站）」（推荐，商标出现在括号里，且说明用途）
   - 改名为「哔哩哔哩 AI 总结助手」→ **不建议**，商标直接用作品牌名，风险最高

   改名要同时改 `src/core/config/app.ts` 的 `APP_NAME` / `APP_SHORT_NAME`，`tests/app-meta.test.ts` 会校验长度上限。

## 2. 详细说明（可直接粘贴）

```
【它做什么】
在 B 站视频页右侧信息栏加一个「AI 总结视频」入口，点开就在下方展开面板：读取该视频的字幕，交给你自己配置的大模型，生成结构化摘要与带时间戳的章节。点任一章节可跳转到视频对应位置。

【为什么需要你自己填模型】
扩展本身不带任何 AI 能力，也不经过任何中转服务器。你在设置里填入任意兼容 OpenAI Chat Completions 协议的服务（OpenAI、DeepSeek、Moonshot、本地 vLLM / Ollama 等）和自己的 API Key，请求由你的浏览器直接发往该地址。好处是费用与数据都在你手上；代价是需要先花两分钟配置。

【主要功能】
· 摘要 + 章节：章节带 [mm:ss] 时间戳，可点击跳转
· 长视频不截断：超过单次请求长度时按句子与时间点切块，分段总结后再合并；失败只重跑未完成的段
· 字幕没有也能做：可选「按画面识别」，自动抽帧交给视觉模型描述画面，结果标注来源
· 导出：Markdown 文件、幕布大纲（复制后粘贴）、字幕 txt
· 知识点与思维导图：把关键要点和带时间戳的章节排成一张思维导图，在面板里就能看，也能导出 SVG（矢量，放大不糊）或 PNG（2 倍分辨率，直接贴进文档与幻灯片）
· 多分P 视频按分P 独立缓存，切 P 不会串内容
· 结果自带「素材指纹」：标明依据多少条字幕、覆盖哪段时间、第一条原文是什么，方便判断总结是否对得上视频

【适合谁】
看长视频、讲座、访谈、技术分享，想先看结构再决定要不要看的人；以及需要把视频内容整理成笔记的人。

【隐私】
不收集浏览历史、Cookie、剪贴板；没有统计与广告；不含任何远程代码。字幕只在你点击总结时发送给你自己配置的模型服务。完整说明见隐私政策。

【说明】
非官方扩展，与哔哩哔哩无隶属关系。「B站 / 哔哩哔哩」仅用于说明适用网站。
```

## 3. 权限用途说明（后台逐条会问）

| 权限 | 后台填写的理由 |
| --- | --- |
| `storage` | 保存模型配置、字幕缓存、总结结果与任务进度。全部数据保存在用户本机，扩展没有服务端。 |
| `activeTab` | 用户点击扩展图标时读取当前标签页 URL，判断是否为 B 站视频页并取到 BV 号。不申请常驻的 `tabs` 权限。 |
| 主机权限 `https://api.bilibili.com/*` | 读取视频信息（标题、UP 主、分P 列表）与字幕轨道地址。仅在 B 站视频页触发。 |
| 主机权限 `https://*.hdslb.com/*` | 下载字幕文件本身（B 站把字幕放在该 CDN 域名下）。 |
| 可选主机权限 `https://*/*`、`http://*/*` | 用户在设置页点「授权该域名」后才生效，用于访问用户自己填写的模型服务。默认不授予，扩展在未授权时不会发起任何模型请求。 |
| 内容脚本 `https://www.bilibili.com/video/*` | 在视频页注入入口按钮与面板容器，并读取页面里 `<video>` 的当前帧用于可选的画面识别。 |

**单一用途声明（Single purpose）**：本扩展只有一个用途——读取 B 站视频的字幕或画面，用用户自己的大模型生成摘要与章节，并支持导出。

**还差一张最重要的：视频页展开面板的截图，需要你自己补。** 原因是生成一张有真实摘要的面板截图必须有你登录态的 B 站字幕 + 你有效的 API Key，验证环境两样都没有，强行截出来只有「字幕未获取 / 视觉模型未配置」的空状态，放进商店反而降低转化。建议这样拍：

1. 在真实浏览器里打开一个有你感兴趣的、**有字幕**的视频（避开弹幕密集的搞笑视频，弹幕属于第三方内容，商店不欢迎）
2. 点右侧「AI 总结视频」，选字幕，等摘要与章节出来
3. 把浏览器窗口调整为 1280×800 的内容区，用系统截图工具截取这一区域（Windows 用 `Win+Shift+S` 框选，或整屏截图后裁切到 1280×800）
4. 保存为 `store/screenshots/00-panel.png`，在商店后台把它排在第一位

截图顺序建议：面板（主图）→ 设置页模型服务 → 分块抽帧 → Popup。

## 6. 提交流程

1. `npm run release`，产出 `release/bilibili-ai-summary-1.0.1.zip`
2. 打开 [Chrome Web Store 开发者后台](https://chrome.google.com/webstore/devconsole)，首次需支付一次性 5 美元注册费
3. 新建项目 → 上传 zip
4. 逐项填写第 1–4 节内容，上传第 5 节图片
5. 提交审核（通常 1–3 个工作日，涉及 `host_permissions` 的会更久）

## 7. 审核容易被退回的点（按本项目的实际情况）

1. **描述与实际功能不符**：简介里写了的东西必须真能用。`tests/app-meta.test.ts` 双向校验——写了「思维导图 / SVG / PNG」就必须存在对应实现文件，没实现的能力不允许出现在简介里。历史教训：v0.1.0 的简介里写了思维导图导出，但当时还没实现，这类文案在审核里属于「虚假宣传」。
2. ~~隐私政策留占位符~~：已填真实邮箱与仓库地址（`PRIVACY.md` 文末）。
3. **宽泛主机权限**：`optional_host_permissions` 写了 `https://*/*`。这是为了让用户连接任意模型服务所必需，理由要写清楚（第 3 节已给出），并强调**默认不授予、需用户在设置页主动点授权**。
4. **截图里出现他人内容**：截 B 站页面时避免拍到评论区用户头像与昵称，或对截图做模糊。
5. **商标**：见第 0 节。

## 8. 上架之后

- 版本号每次上传必须**严格递增**（1.0.0 → 1.0.1）。`npm run release` 会校验 `package.json` 与 `app.ts` 一致，但不会替你判断是否大于线上版本。
- 用户更新后 `chrome.storage.local` 里的旧设置会保留，`normalizeSettings` 会自动补齐新增字段（见 README §4），不需要让用户重填。
